# EI-Eval pilot v0.1

This maintainer-run pilot compares the native Codex CLI with Engineering-Infrastructure at commit `0f274aa97682c86514cfc6738a792790e3f810b8`. The goal is to test the measurement pipeline and identify cases worth a larger study. The frozen task fixtures, prompts, verdicts, order and budgets are in `pilot.py`. Its SHA-256 and the exact subject commit appear in each run's receipt.

- **A, native** uses the bundled default agent capabilities and a fresh home. **D, full** uses a real isolated Codex bootstrap from the pinned project revision, with all three CORE Skills and the default `REPORT_ONLY` policy. **B, prompt-only** adds equivalent written goals to the native configuration for the PR and Git integration tasks. There is no Workflow-only C condition in this pilot.
- Six task blocks each receive A and D, with alternating balanced order. Two blocks also receive B at complementary positions. The host runs one trial at a time. Every trial has one fresh checkout, isolated home and XDG roots, and an ephemeral session. Identical task prompts, starting trees, verifiers, sandbox mode, model, reasoning effort and 150-second session limits apply. Login is reused through the configured native CLI. Users should run only against a supported Linux environment with a signed-in file-backed Codex installation.
- Primary outcome is the condition-blind artifact verifier's binary result. It scores program behavior, Git and working tree state, or concrete PR facts. Score failures, timeouts and refusal to produce the required artifact as unsuccessful. Record infrastructure failures separately without replacing the trial. Baseline fixture negative checks and positive oracle checks precede every model invocation.
- Secondary outcomes are wall-clock session time, setup and validation time, reported input, cached input and output tokens, intervention, and activation evidence in the tool trace. Token fields are unavailable when the CLI emits no usage. Preserve the measured overhead, including failures. The CLI does not expose provider billing, exact service build, or a configurable hard token ceiling for this run.
- Summarize paired wins, ties and losses by **task**, per-condition completion counts, and all-attempt time and tokens. With six selected tasks and one trial per condition, treat all contrasts as exploratory. The PR rubric scores checkable content, so it cannot estimate human review acceptance.
- Stop after the frozen 14 attempts or after two consecutive CLI startup failures without model activity. A fixture/setup failure before invocation stops the batch and is reported separately. Preserve raw events, stderr and scored task artifacts locally. Publish only allowlisted metrics, outcome codes and content fingerprints. An unreached trial is not an attempt.

The six cases cover small Python behavior, preservation on preview, PR factual accuracy, deployment freshness, integrating independent Git refs without touching ongoing work, and an unresolved metadata defect in the public Engineering-Infrastructure repository. The other fixtures are synthetic. The last case starts from the public subject tree in a disposable repository. The official benchmarks and long-horizon work have separate eligibility and budget decisions.
