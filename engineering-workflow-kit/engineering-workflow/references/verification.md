# 证据与质量门禁

## 证据记录契约

每条检查一条记录：`id / cmd / cwd / exit_code / status / state / duration / note`。`state` = HEAD（+未提交内容哈希），由 `ewk.py run` 自动写入。规则：

- PASS 必须有 cmd 且 exit_code 0；手写 PASS 会被 `ewk check` 拒绝。
- 代码或环境变了，旧 PASS 视为 STALE，须重跑；不是“再解释一下”。
- NOT_RUN / BLOCKED / PENDING / NOT_APPLICABLE 必须写原因。
- 区分：静态检查（编译/lint）≠ 实际运行 ≠ CI；构建成功不是运行测试；mock 不是实机。交付时分栏列出。
- 校验脚本本身要有测试；取证失败返回非零，默认不成功。
- 不记录秘密；`output_tail` 交付前自行脱敏。

## 质量维度（按变更触发，不全量跑）

功能正确性 · 架构/可维护性 · 运行稳定性 · 性能资源 · 安全隐私 · 兼容性 · 可观测性 · 可回滚性。快检在前，重检按风险触发。最终交付满足仓库规定的必需检查。

## 测试写法（Validated global）

- 测行为，经真实代码路径；能证明旧缺陷会让它失败（负控制：把旧 bug 放回去，检查必须红）。
- 不用绝对时间阈值（CI 机器慢会红），断言顺序或区间重叠；不写位置相关断言（仓库换个盘符或用户目录就挂）。
- 不写靠正则读源码文本的“守卫测试”冒充行为测试；不可测的行为（模态框、布局）在交付里写明。
- 并行/合并多个改动前做一次试合并再构建，防同名符号冲突。

## 性能声明字段

没有基线与测量就不说“改善”。必须写：base/head、设备/OS、构建模式、工具、场景/负载、预热、采样次数与统计量（median/p95/p99）、不确定性、模拟/推断/实测之分。相对变化 `(candidate-baseline)/baseline`。基线与候选同条件。

## 领域验证（按本机实际项目类型选；缺失则用最小夹具并声明非生产实测）

| 领域 | 触发 | 验证能力 |
|---|---|---|
| 桌面/UI/动画/主题 | 界面、动效、窗口生命周期 | 可运行驱动（热键/UIA/测量钩子）操作关键路径；同环境前后对照截图/录屏；状态切换与中断；DPI/主题/对比度；订阅与资源在窗口关闭时释放；用 `Stopwatch` 级单调时钟排序事件；CPU/GPU/内存与帧时间分位。不抢用户前台/鼠标；GUI 无法运行则 BLOCKED。 |
| Web / 扩展 | 前端、权限、网络 | 浏览器 E2E；DOM/交互；可访问性；响应式；权限边界；网络失败；生命周期。 |
| 服务端 / CLI | 接口、数据、并发 | 契约/集成测试；错误恢复；幂等；并发；输入边界；退出码；日志/指标。 |
| ML / 科研 | 实验、评测 | 数据/代码版本；随机种子；环境与配置；预先登记的验收；基线/消融；防数据泄露；不选择性报告；不宣称未分析的显著性。 |
| 持久化状态/配置 | 设置、枚举、schema | 候选 vs 现网的键与枚举值逐项对照；绝不重编号既有枚举；会改变用户已配置值含义须先问；部署后对比备份与现网差异。 |
| 安全/高风险 | 权限、秘密、依赖 | 威胁点列举；权限检查；秘密扫描（`ewk guard`）；依赖与许可证；负例；必要时供应链溯源。 |
| 状态机/并发/算法 | 竞态、不变量 | 先属性/模型测试；按价值再考虑 TLA+/Lean；检查模型与实现对应；模型通过≠实现正确。 |

## 不稳定与失败

flaky：复现、定位原因（时序/共享状态/环境）、修；不重跑到绿。全量失败而单测通过时，先在纯基线分支跑同一测试，再判断是否自己改动所致。
