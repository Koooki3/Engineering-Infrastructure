# 纠正阶梯（反复犯同类错误时）

触发：同一错误第二次出现，或用户说“又犯了 / 再加条规则”。不要再往全局或项目指令里追加一句警告。与 Claude 侧 `constraint-ladder` skill 同一阶梯；两者择一执行，不叠加。

## 顺序

1. **设计层**：改 API/目录/类型/依赖边界，让错误选项不存在。
2. **检查层**：变成 lint、类型、依赖边界、测试或 hook；报错信息写明正确做法。先扩展项目已有入口（lint 配置、CI、`.git/hooks`、测试目录），不另起炉灶。
3. **工具层**：做成可重复运行、自身有测试的验证命令。
4. **按需 Skill / 短指令**：只有前三者做不到、确属判断类规则才写文字，且写进项目，不写进全局。

## 步骤（≤7）

1. 复述错误并给出现次数与位置；完成标准：一句话说清“错误类”。
2. 查项目现有检查入口。
3. 按阶梯选层，先试设计层。
4. 选检查层时：通用的字符/路径/密钥类用 `ewk.py guard`，在仓库根 `.ewk.json` 配 `protected_paths / local_path_re / bases`。
5. **负向验证**：故意造一个违规改动，确认检查失败且提示可执行；再在真实分支确认不误报。
6. 需要拦截推送时挂 `.git/hooks/pre-push` 调用检查（hooks 在 git common dir，不进提交；先读已有 hook，不覆盖）。
7. 汇报：加了什么、验证了什么、没覆盖什么。`--no-verify` 绕过只能由用户决定。

## 晋升与退役

- 误报、运行成本或复杂度超过收益 → 不晋升，记录原因。
- 项目局部经验不上升为全局规则；晋升全局须有跨独立场景证据。
- 检查连续长期无触发且对应设计已消除错误 → 退役该检查，保留记录。

## 附带

- 清理仓库里相邻的废弃写法和临时变通：Agent 会模仿已有代码。
- 不用注释给已知坏写法开脱；要么修，要么留 TODO 并指向检查/任务。
- 先内环（代码质量、约束、验证）再外环（循环、定时、自动合并）；内环不可靠时不加外环。
- 外部数字（如某团队的 PR 数、回滚率）是自报，不是对照实验；具体框架规则是其本地选择，新项目先看自身技术栈。
