# 已蒸馏的通用规则（项目无关）

等级：`VG` Validated global · `VD` Validated domain · `C` Candidate（未验证，不强制）。来源 ID（Fxx）对应本机证据，见 kit 的 `reports/evidence-and-decisions.md`；发布/迁移版可去掉该列。

| ID | 规则（不变量） | 等级 | 范围 | 最小约束 | 来源 |
|---|---|---|---|---|---|
| L01 | 完成 = 真实命令的退出码 + 绑定当前状态；自述、编译通过、测试数量都不算 | VG | 全部 | `ewk run/check` | F01 F13 |
| L02 | 任何等待必须有上限与归属；子 Agent 的“已清理”要核对 | VG | 脚本/后台任务/Agent 交接 | `ewk run --timeout`；结束后查遗留进程 | F03 |
| L03 | 会对外发布内容的工具，负向测试只能在 dry-run 下做 | VG | 含 gh/邮件/部署的脚本 | 工具提供 DRY_RUN；首次真实使用只在自己的对象上 | F04 |
| L04 | 加探针前先 WIP 提交；移除探针用精确编辑，不对含未提交改动的文件用 checkout/reset | VG | 含未提交改动的诊断 | 先 `git status`；探针放独立文件 | F05 |
| L05 | 测试行为，不读源码文本；能证明旧缺陷会让它失败 | VG | 测试 | 负控制：恢复旧 bug 检查必红 | F06 F08 |
| L06 | 不用绝对时间阈值、不依赖仓库所在位置 | VG | 测试/CI | 断言顺序或区间重叠 | F07 |
| L07 | 持久化设置：对照键与枚举；不重编号；含义变化先问用户 | VG | 配置/schema/部署 | 部署前 diff 候选与现网；部署后 diff 备份 | F09 |
| L08 | 依赖环境的结论要在用户所处环境验证（容器/注册表/WSL/DPI） | VG | 环境相关断言 | 在宿主环境复核再下结论 | F14 |
| L09 | 校验/部署门禁自身需要测试，且取证失败不得通过 | VG | harness | 桩化外部依赖的隔离回归；失败退出非零 | F13 F02 |
| L10 | 同一错误第二次出现，先改设计，其次机械检查，最后才写文字 | VG | 全部 | 见 correction-ladder | F01 F02 |
| L11 | 编码/BOM/本地路径/密钥类错误用机械检查，不靠提醒 | VG | Windows+中文源码、公开仓库 | `ewk guard` | F02 |
| L12 | 窗口生命周期内的订阅（静态事件、属性监听）须在关闭时移除；重试不得无条件自我重投递 | VD | 桌面 UI | 代码评审清单 + 泄漏回归 | F07 F10 |
| L13 | 事件排序用单调高分辨率时钟；忙机/低速机路径单独测 | VD | 桌面/动画/时序 | Stopwatch 级时钟；占满 CPU 的负载测试 | F07 |
| L14 | GUI 实测用隔离实例与副本设置，不抢用户前台/鼠标，不改真实设置 | VD | 桌面实机 | 项目驱动 + 设置只读 | F09 F12 |
| L15 | 大型视觉/系统改动：修复者与复核者分离，复核者回访自己上轮条目，直到无新发现 | VD | Critical 视觉/系统 | 独立复核；轮数由新发现决定 | F08 |
| L16 | 预算用于防失控，不用于压缩必要验证；不为“防御”给低风险动作加门禁 | C | 全部 | 用户已表态时按用户 | F11 F15 |
| L17 | 单一入口部署：只走项目既有部署脚本，先读脚本，不拼临时命令 | VD | 有部署脚本的项目 | 脚本门禁 + 部署台账 | F13 |

## 已拒绝/限定

- 固定轮数的多 Agent 评审、无限修复循环：拒绝（用新发现与预算控制）。
- 以 PR 数/LOC/测试数/Agent 数为目标：拒绝。
- 把某项目的路径、框架偏好、版本前缀写进全局：拒绝（留在项目）。
- 对 GPU 类测试的过度防御：限定为“经守卫脚本逐个运行”，不扩展为全局门禁。
